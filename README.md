# 多地点损失依赖分析（合成实验）

一个可以跑起来的风险数据分析页：导入**虚构**的多地点月度损失记录，先分别拟合各地点的边际分布，再比较 **Gaussian copula** 与 **Student-t copula** 两类依赖模型生成的联合场景，把「尾部同时超限」的差异直接摆出来。

> 所有金额均为合成实验数据，不来自任何真实标的，也不构成任何风险度量。

---

## 1. 这个页面要回答的问题

几个地点的损失有时会同时变大。只看每个地点各自的边际分布，**无法**推出总损失的分布，也**无法**估计「同一个月多个地点一起超限」的概率——这取决于它们之间的相依结构，尤其是上尾的相依结构。

页面把这个问题拆成一条可验证的链路：

1. **边际**：每个地点用自己观测到的月份拟合 severity 分布（对数正态 / Gamma / Weibull 按训练期 AIC 选择）。
2. **依赖**：只在**所有被选地点都观测到的月份**上估计 Kendall's τ → 相关矩阵，再投影成合法相关矩阵。
3. **两类假设**：同一个相关矩阵下的 Gaussian copula（无尾部依赖）与 Student-t copula（对称尾部依赖，自由度 ν 由训练期似然估计）。
4. **模型选择**：只使用**训练期**。
5. **评估期**：用训练期的边际分位数作为固定阈值，检验两套模型对**联合超限覆盖率**的预测，报告精确二项区间，而不是硬给一个通过/失败。
6. **成员变更**：新增地点 = 新的联合样本 = 新的签名；旧场景**不能**加一列继续用。

## 3. 内置合成数据（真相已知）

`server/data.py` 生成一个月度面板：

| 项目 | 设定 |
|---|---|
| 期间 | 1985-01 → 2024-12，共 480 个月 |
| 地点 | harbor / inland / coast / ridge / delta |
| 边际 | 对数正态（参数即真相） |
| 依赖真相 | **Student-t copula，df = 3.5**，相关矩阵已知 |
| 缺测 | 每个地点独立缺测（0.015–0.04），`delta` 从第 24 个月才加入 |
| 成员版本 | `core-four`（第 0 月起）、`all-five`（第 24 月起） |

这样安排的目的：

- **边际相同、尾部依赖不同**：Gaussian copula 能复现同样的秩相关和边际，但上尾没有相依；Student-t copula 有。于是「联合超限率」的差异是生成过程里真实存在的，而不是数值假象。
- **参差不齐的日历**：`delta` 晚 24 个月加入，各地点缺测月份不同——联合样本必须取交集。
- **一对刻意弱相关**：`harbor × inland` 的真实相关只有 0.08。即使真相是 t copula，这一对的联合上尾样本也极少，页面必须把它标成「不稳定」。

## 4. 统计方法（以及为什么这样做）

### 4.1 缺测日期：共同观测，而不是各自排序后硬拼

这是整个页面的核心约束。

- **边际**：每个地点在自己的观测月份上拟合（`n_obs` 为该地点自己的观测数）。
- **依赖**：只用**共同观测**月份（listwise-complete）。copula 的输入是这些月份里各地点边际 CDF 值 `u = F_j(x_j)`，不是「各自排序后的秩」。
- **显式报告**：`calendar.joint_months`、`calendar.per_site_observed`、每对地点的 `common_months`、`n_first_extreme` / `n_dual_extreme` 都写进结果。

为什么不能「各自排序再拼」：把每个地点独立排序再按行拼接，等价于人为制造一个秩的对应关系，得到的相关性与尾部结构完全由拼接方式决定。测试 `test_copula_inputs_come_from_jointly_observed_months` 用同样的数据重算 copula 输入，能逐位复现报告的相关矩阵；`test_ranking_each_site_separately_would_change_the_answer` 则展示「硬拼」会得到不同的矩阵。

### 4.2 参数矩阵的合法性

秩相关矩阵先由 Kendall's τ 经 `r = sin(πτ/2)` 得到，再做最近相关矩阵投影（交替：裁剪负特征值 → 对角线归一），直到对称、单位对角、PSD。

结果里同时给出：

- `copula.legality`：`symmetric / unit_diagonal / bounded / psd / legal`
- `copula.diagnostics`：`min_eig_before / min_eig_after / max_abs_adjust / condition / adjusted`

API 和测试都会在返回前校验，非法矩阵不会进入场景生成。

### 4.3 模型选择（仅训练期）

- 时间顺序切分：共同月份前 70% 为训练期，后 30% 为评估期。
- 边际族在训练期按 AIC 选择；选定后在整个观测样本上重估参数用于生成场景，但**阈值**（q90/q95）来自训练期拟合。
- Copula：同一个相关矩阵下比较 Gaussian 与 Student-t 的对数似然，AIC 差值决定 `selected`；ν 在训练期估计。

### 4.4 评估期：联合超限覆盖

- 阈值：训练期每个地点边际的 q90 / q95（固定，不随评估期变化）。
- 统计：评估期各地点超限次数、至少两个地点同时超限、全部地点同时超限。
- 区间：Clopper–Pearson 精确二项区间。
- 模型侧：用**训练期**的 copula 与边际生成参考场景，给出模型隐含的联合超限率，再与评估期观测率和区间对照。

因为评估期只有一百多个月、联合事件又稀少，区间会很宽。页面**如实展示宽区间**，不把它包装成「通过」。

### 4.5 极少的共同极端样本 → 估计不稳定

每对地点在 u > 0.90 处计算经验尾依赖 `P(U_j > u | U_i > u)`，并给出 bootstrap 区间。若**双重极端样本数 < 10**，标记 `stable = false`，页面显示不稳定徽标与说明（例如 `harbor × inland` 只有 5 个双重极端月份）。这明确告诉你：这个尾部估计建立在一把样本上，区间很宽。

### 4.6 新增地点：新签名，禁止追加列

每次拟合生成 `signature`（sha256 前 20 位），来源包括：研究 id、排序后的地点集合、成员版本、各边际族与参数、相关矩阵、ν、场景数、种子、训练比例。

- 改变地点集合 → 签名改变 → 旧的场景缓存不可用。
- `/api/fit` 若带 `parent_signature` 且地点集合不同，返回 **409 `membership_changed`**，并给出前后版本与地点。
- 场景缓存是内存 LRU（6 组），未知签名下载返回 404，提示重新拟合；不会把新地点拼到旧场景上。

### 4.7 一致性检查（页面「校验」页）

对每套模型：

- **边际一致性**：模拟损失对拟合分布做 KS 检验（p > 0.01），均值相对差在 `3·sd/√n` 的蒙特卡洛容差内。
- **相关性一致性**：模拟损失的 Kendall's τ 与目标 τ 最大偏差在容差内（`max(0.03, 3·τ 标准误)`，小场景数时自动放宽）。
- **聚合一致性**：`E[Σ X_j] = Σ E[X_j]`（恒等式，对模拟样本精确成立；与拟合边际均值的偏差用 `3·sd/√n` 的蒙特卡洛容差判断，避免把场景数少误判成偏差）。

两套模型共用同一组随机数（common random numbers），所以它们的差异只来自 copula 的尾部假设，而不是随机波动。

## 5. 结果解读向导

在默认数据与种子（2611）、core-four、20000 个场景下（这些数字会随种子略变，测试校验的是结构而不是钉死数值）：

| 指标 | Gaussian | Student-t | 观测共同月份 |
|---|---|---|---|
| 总损失均值 | ≈ 292.5 | ≈ 292.4 | ≈ 293.9 |
| 总损失 q99.5 | ≈ 555 | ≈ 591 | — |
| 至少 2 地点同超 q95 | ≈ 3.3% | ≈ 4.3% | ≈ 4.6% |
| 全部地点同超 q95 | ≈ 0.06% | ≈ 0.3% | 0%（433 月中 0 次） |
| 训练期 AIC 选择 | — | ✅（ν ≈ 3.4，ΔAIC ≈ 79） | — |

要点：**均值几乎一样**（聚合恒等式），**联合尾部差一个量级**。Gaussian copula 会系统性低估「多地点同时爆表」的概率。

## 6. API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/study` | 合成数据、地点、月份、原始记录、成员版本 |
| POST | `/api/fit` | `{sites, scenarios, seed, train_fraction, parent_signature?}` → 完整结果（含签名） |
| GET | `/api/scatter` | `?signature=&model=&a=&b=&n=` 两地点场景散点（沿总损失顺序均匀抽样，保住上尾） |
| GET | `/api/scenarios.csv` | `?signature=&model=&uniforms=` 完整场景（`scenario,<site>…,total[,u_<site>…]`） |
| GET | `/api/params.json` | 参数、诊断、合法性、评估、签名来源、`scenario_set` |
| GET | `/api/records.csv` | 原始合成记录 |
| GET | `/api/health` | 健康检查 |

`POST /api/fit` 的错误码：

- `409 membership_changed`：`parent_signature` 的地点集合与本次不同；
- `422 fit_failed`：统计上无法拟合（例如地点太少、共同月份不足）；
- `404 unknown_signature`：场景集已不在内存，需重新拟合。

## 8. 已知边界

- 评估期只有约 130 个月，联合超限事件稀少，覆盖检验的区间天然很宽——页面展示区间而不是二值结论。
- 经验尾依赖在弱相关对上不稳定，页面显式标注；这不是 bug，而是本页要展示的现象之一。
- 场景集保存在进程内存（最多 6 组），服务重启后需重新拟合。
- 前端无构建步骤、无第三方图表库；浏览器截图验证受运行环境缺少系统库限制，功能验证通过 jsdom 冒烟测试与 API 测试完成。
